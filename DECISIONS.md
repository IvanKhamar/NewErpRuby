# Decisions

Decisions made while the user was away. Each: what, why, and the options considered. Newest at the bottom.

## D1. Scope: every module of the brief, a focused set of endpoints each

- **What:** port each module the brief lists, with the endpoints in `PLAN.md`, keeping the reference contract exactly.
  The rest of the 369 reference operations are listed as gaps.
- **Why:** the reference is ~40k lines; the brief says idiomatic, explainable Rails matters more than feature count.
- **Options:** (a) port everything — not possible with quality in one run; (b) only orders and stock — misses the
  brief's integrations, jobs and Kafka; (c) chosen: all modules, fewer endpoints each.

## D2. API paths stay at the root, the Ruby namespace is `Api::V1`

- **What:** `GET /orders`, not `GET /api/v1/orders`. Controllers live in `app/controllers/api/v1` and routes use
  `scope module: "api/v1"`.
- **Why:** the brief says the reference wins on conflicts, and the contract (`docs/openapi.json`) has no `/api/v1`
  prefix. Web interfaces of the other versions call these exact paths.
- **New module:** the refund check (not in the reference) follows the same style: `POST /refunds/recipient-checks`
  instead of the brief's `/api/v1/refunds/recipient_checks` (kebab-case like every other contract path).

## D3. Full Rails app, generated in Docker; no native Ruby on Windows

- **What:** `rails new` ran inside `ruby:4.0.10`; every command runs through `docker compose run --rm app …`.
- **Why:** the machine has no Ruby (WSL Ubuntu exists but has no Ruby either); Docker is installed and running, and
  the same image then serves development, tests and the compose setup. Installing Ruby into WSL was the option
  not taken: one more environment to keep in sync.
- **Skipped generators:** Solid Queue/Cache/Cable (Sidekiq and Redis are the brief's choice), Kamal, Thruster,
  Active Storage, Action Text, Mailbox, Mailer, Cable, Rails' production Dockerfile, Rails' own CI and RuboCop
  omakase (replaced by own CI and a RuboCop config with the rails, rspec and performance plugins).

## D4. Secrets: ENV only, no Rails credentials

- **What:** `config/master.key` and `config/credentials.yml.enc` generated by `rails new` were deleted before the
  first commit. Production reads `SECRET_KEY_BASE` and every key from ENV; development and test use Rails'
  generated `tmp/local_secret.txt` (git-ignored).
- **Why:** the brief says ENV only; the reference keeps secrets in `.env` / env vars too.

## D5. Serializers: Alba, not Jbuilder

- **What:** `app/serializers/*` with Alba, camelCase keys set per serializer (`transform_keys :lower_camel`).
- **Why:** serializers are plain Ruby classes that are easy to unit-test and reuse between endpoints; Jbuilder
  templates spread the JSON shape over view files and are slower. Alba has no dependencies.

## D6. Authentication: Rails encrypted cookie, the reference's password hash format

- **What:** `POST /auth/login` checks the password against `erp_user_login.password_hash` in the ASP.NET Core
  Identity v3 PBKDF2 format (same as the Python, Java and .NET versions) and writes an **encrypted cookie**
  `newerp.auth` with the user id, the security stamp and the issue time. An `Authentication` concern (shaped like
  the Rails 8 authentication generator: `require_authentication`, `allow_unauthenticated_access`, `Current.user`)
  checks the stamp on every request, so a role or password change ends old sessions.
- **Why not the generator as is:** it creates a `users` table with bcrypt `has_secure_password` and a `sessions`
  table. The database is shared with three other versions, so the hash format and the tables must stay.
  Reference wins (brief §1.6).

## D7. Stock changes: pessimistic locking (`lock!`)

- **What:** every stock change loads the row with `SELECT … FOR UPDATE` inside a transaction.
- **Why:** the brief asks for it (like the Java version). The Python reference uses a compare-and-set on the quantity
  (SQLAlchemy `version_id_col`) and answers 409 on a race; with a lock the second request waits instead and both
  succeed. The final stock is correct either way; the contract does not change. The stock tables are InnoDB, so
  row locks work. The OpenCart order tables are MyISAM (no transactions), as the reference notes too.
- **No optimistic locking:** the legacy tables have no `lock_version` column, and the brief says not to add one.

## D8. Time: Kyiv wall clock without a zone, as the database keeps it

- **What:** `config.time_zone = "Kyiv"`, `active_record.default_timezone = :local`, and the process zone is set to
  `Europe/Kyiv` at boot. JSON writes times as `2026-01-01T10:00:00` (no offset), like the reference.
- **Why:** the old site and all versions store local Kyiv time in `datetime` columns. With `:utc` Rails would shift
  every value by two or three hours.
- **Contract tests:** the contract marks these fields `format: date-time`, which `openapi_parser` reads as RFC 3339
  with an offset. The spec helper loads the contract and swaps that format for a pattern of local date-times; the
  file `docs/openapi.json` itself stays unchanged.

## D9. Schema: legacy DDL loaded once, own tables by migrations, `structure.sql`

- **What:** `db/reference_schema.sql` (DDL from the reference's `db/*.sql`, no data) is loaded by the first
  migration. `config.active_record.schema_format = :sql`, so `db/structure.sql` keeps MySQL details
  (MyISAM engines, enum columns) that `schema.rb` would lose.
- **Why:** database-first like the reference, but `bin/rails db:prepare` alone builds a working database for
  development, tests and CI.

## D10. Services return a Result; models raise DomainError

- **What:** `ApplicationService.call` returns `Result` (`success?`, `value`, `error`, `kind`). A single-entity rule in
  a model (`StockItem#adjust`) raises `DomainError`; `call` turns it into a failure after the transaction rolled back.
- **Why:** the brief asks for an explicit success/failure result; raising inside a model keeps the transaction
  rollback automatic. **Options:** dry-monads (one more gem, more to explain), exceptions only (like the reference).

## D11. Small contract details kept from the reference

- `GET /orders/{id}` for an unknown order answers 404 with the English title "Not Found" (the reference does it
  this way for this one endpoint); the others use "Не знайдено".
- `GET /health` answers `Healthy` as plain text.
- The customer risk of a new order has no `sharedIp` part (the reference also searches many customers behind one IP
  address); the field is always `null`, which the contract allows. Listed as a gap.

## D12. CI runs in the ruby:4.0.10 container

- **What:** the test job uses `container: ruby:4.0.10` with MySQL and Redis services, not `ruby/setup-ruby`.
- **Why:** Ruby 4.0.10 came out on 2026-11-19; a prebuilt binary for setup-ruby may not exist yet, and a failed CI
  run e-mails the user. The container is the same image as `Dockerfile.dev`, so local and CI runs match.

## D13. Tests and MyISAM

- **What:** transactional fixtures roll back InnoDB tables; after each example the non-empty MyISAM tables
  (OpenCart's) are emptied (`spec/support/myisam_cleanup.rb`). The concurrency test runs without a transaction
  and removes its own rows.
- **Why:** MyISAM ignores transactions, so rows written by a test would leak into the next one.

## D14. Phase 2 choices

- **Schedule:** pre-orders hourly, competitor prices daily at 07:00, tracking hourly at :30, all in Kyiv time
  (`config/schedule.yml`). The reference makes the pre-order interval and the check time settings; here they are
  fixed in the YAML file, which is the usual sidekiq-cron way.
- **Tracking client:** the hourly refresh uses the domestic Nova Poshta API (as the reference does); Nova Post
  International comes in phase 3. Without `NEWERP_NOVA_POSHTA_API_KEY` the stub answers "not configured".
- **Page fetcher on Net::HTTP, not Faraday:** it must connect to the IP address it checked (`Net::HTTP#ipaddr`) to
  stop DNS rebinding; Faraday's adapters do not expose that. The outside-service clients use Faraday.
- **ReDoS test:** Ruby 3.2+ memoizes regex matching, so the classic `(a+)+$` no longer hangs; the test uses a pattern
  with a backreference, which turns memoization off, to prove the timeout really fires.
- **Lesson:** `rubocop -A` rewrote `!ip_range.include?(ip)` into `ip_range.exclude?(ip)`, which IPAddr does not have.
  The tests caught it; those two lines now carry an inline exemption with the reason.

## D15. Phase 3: one meaningful flow per outside service

- **LiqPay:** checkout link and payment status (`/orders/{id}/liqpay-link`, `/orders/{id}/liqpay-status`).
- **PrivatBank:** statement import and the payment list (`/payments/bank/import`, `/payments/bank`). The automatic
  linking of payments to orders after the import is not ported (`autoLinked` is optional in the contract and left out).
- **SMSClub:** send to the order's phone and the order's SMS log. The reference's check that a waybill number in
  the text belongs to the same order (`ttnMismatch`) is not ported; the field is always `null`.
- **Checkbox:** fiscalizing a receipt Checkbox has not accepted (`/cashbox/cheques/{id}/fiscalize`); opening and
  closing shifts, X/Z reports are gaps. ChequeDto's `warehouse` and `requisites` are `null` for the same reason.
- **Nova Post International:** creating a waybill abroad (`/orders/{id}/shipment/international`); HS code search and
  deleting are gaps.
- **Keys:** all from ENV (`.env.example` lists the names). The Checkbox keys the old site keeps in
  `dd_cashbox_user` are never read (`ignored_columns`), as in the reference.
- **Retries:** only for requests safe to repeat (GET, Nova Poshta tracking). A sale, a waybill and an SMS are never
  retried automatically: a repeat would make a duplicate.

## D16. Phase 4 choices

- **Sanitizing:** the reference cleans editor HTML in catalog content (pages, FAQ, descriptions). The FAQ
  (`/catalog/faq`) was ported as the place where it really happens. `SafeListSanitizer` keeps a `<script>`'s text,
  nh3 drops it; `HtmlContent` removes such elements with their content first, so both behave alike.
- **Stocktaking preview** reads the raw request body (an .xlsx), exactly as the reference does, not a multipart form.
- **Partner feed:** anonymous by partner code, as in the reference (an earlier line of PLAN.md said "with a token";
  that was wrong and is fixed). Shop name, company and store URL come from ENV (`NEWERP_FEED_SHOP_NAME`,
  `NEWERP_FEED_COMPANY`, `NEWERP_STORE_URL`).
- **Sales report:** `group` accepts the names (Day, Week, Month, Year) and their numbers, like the reference.

## D17. Order events: after commit, no outbox

- **What:** events are published in `ActiveRecord.after_all_transactions_commit`; a Kafka failure at that moment is
  logged and the event is lost (the order stays).
- **Why not a transactional outbox:** the order tables are MyISAM, so an outbox row could not be written atomically
  with the order anyway; the reference makes the same choice and says so. Producer settings `acks: -1` and
  idempotence keep the broker side safe; `eventId` lets consumers skip repeats.
- **Lesson:** the publisher was first kept in `config.x`, which returns an empty `OrderedOptions` for an unset key,
  so no publisher was ever set and events went nowhere. Only the real round trip through Kafka showed it. Now it is
  `OrderEvents.publisher` (`mattr_accessor`), with a spec on the default.
- **Checked by hand:** with `docker compose --profile kafka`, a status change put
  `{"type":"OrderStatusChanged",...}` with key = order id into `newerp.orders`.

## D18. Refund recipient check (the new module)

- **Paths:** `POST /refunds/recipient-checks`, `GET /refunds/recipient-checks`, `POST /refunds`: the contract's style
  (kebab-case, no `/api/v1`) instead of the brief's `/api/v1/refunds/recipient_checks` (D2). Not in
  `docs/openapi.json`, so their specs check the JSON directly.
- **Known accounts:** a local table `erp_refund_known_account` stands in for a bank's Confirmation of Payee service;
  seeds put two invented holders on IBANs built with valid check digits.
- **IBAN countries:** the lengths of 27 countries from the SWIFT registry (Ukraine and the usual neighbours and EU);
  any other country is refused with a clear message rather than checked by format only.
- **Matching:** same words in any order after normalization = match; every word at least 80 % similar (Levenshtein)
  and at least first and last name = close match; else no match. The threshold is a starting point to tune on real
  data, which this portfolio project does not have.
- **Privacy:** the holder's name is returned only for a close match (as a hint to fix a typo), never for no match.
- **Invalid IBAN:** answered with 400 and the reason, and still written to the audit log as `invalid_iban`.
